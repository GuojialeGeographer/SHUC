## 1. 项目定位与核心目标

### 1.1 关键洞察：从"山地方法"到"流域身份证"

**用户核心观点（2025-04-02）：**

```
我们不是做树客，我们的重点是最后的流域编码。

核心目标：
- 让每一个流域有一个身份证（唯一编码）
- 流域面积大小合理（符合管理需求）
- 空间上下文关系明确（上下游清晰）
- 边界清晰

不是局限于山地，而是要覆盖完整水系：
- 长江流域、淮河流域、珠江流域等
- 从HUC-2到HUC-12（SHUC-2到SHUC-12）的完整体系
```

**决策结论：**
- ❌ 不是：做一个山地流域提取方法
- ✅ 而是：建立中国完整的流域身份证编码体系
- ✅ 必须覆盖完整大流域（包括平原地区）

### 1.2 核心创新点（确认）

```
三大核心创新：
1. 动态阈值自适应算法
   - Q75 + (Q90-Q75)/2 的动态计算
   - 根据数据分布自动调整合并目标
   
2. 拓扑保持的智能合并框架
   - 基于图约束的优化
   - 面积-形状-拓扑三目标权衡
   
3. 完整层级编码体系（SHUC）
   - 6级12位编码（2位一级）
   - 从流域到支流到末端单元
   - 编码体现上下游关系
```

- 数据论文不写算法细节

## 3. 数据源选择决策

### 3.1 数据源方案对比

**讨论焦点（2025-04-02）：**

```
方案A：TauDEM自生产（30m SRTM）
- 优势：完整展示"从DEM到编码"流程
- 劣势：耗时（4-6周），平原地区有问题

方案B：HydroSHEDS（现成数据）
- 优势：快速（1天）
- 劣势：方法链断裂，无法展示完整流程

方案C：MERIT Hydro（90m，已预处理）
- 优势：已填洼、已有流向和累积量
- 劣势：90m分辨率（对中-大流域足够）
- 关键：跳过最耗时的预处理步骤
```

### 3.2 关键决策：使用MERIT Hydro

**最终决策（2025-04-02）：**

```
选择：MERIT Hydro + TauDEM StreamNet + Python优化

理由：
1. 大幅节省时间（6周 → 3周）
2. 数据质量高（已优化处理）
3. 平原地区已改善
4. 可以展示完整方法链（在MERIT基础上优化）
5. 可得到完整拓扑关系

具体策略：
- 使用MERIT的流向（dir）+ 累积量（upa）
- 用TauDEM的streamnet生成拓扑关系
- Python进行SHUC优化（合并+编码）

特别注意：
- 长江流域（+50km缓冲区）
- 淮河流域（平原为主）
- 珠江流域（水网复杂）
- 3大流域，共40,000+流域
```

### 3.3 平原问题的解决方案

```
平原地区不是障碍，而是需要解决的问题：

解决方案：
1. 多源数据融合（推荐）
   - MERIT DEM + 遥感水体（Sentinel-2）
   - 现有水系数据（OSM）约束
   - 人工水利设施标注

2. 分层处理策略
   - 上游（山地）：标准处理
   - 中游（丘陵）：TauDEM + 修正
   - 下游（平原）：大阈值 + 人工辅助

3. 坦诚说明局限
   - 论文中明确标注平原区域处理方法
   - 说明不确定性
   - 作为未来研究方向
```

## 4. 技术实现方案

### 4.1 拼接策略决策

```
拼接方案对比：

方案A：先拼接成大DEM，再整体处理（推荐）
- 适用：单一大流域（如长江）
- 内存：~10-20GB
- 优点：简单可靠，无边界问题
- 缓冲区：50km（确保边界流域完整）

方案B：瓦片分别处理，最后合并拓扑
- 适用：全国范围
- 内存：~2-4GB/瓦片
- 缺点：边界处理复杂

方案C：一景一景，不拼接
- 评价：❌ 不推荐，无法形成完整体系

决策：方案A（长江流域用方案A，其他视情况）
```

### 4.2 拼接工具选择

```
推荐组合：Python GDAL（自动化）+ QGIS（检查）

Python拼接（主要）：
- rasterio.merge（mosaic函数）
- 自动化，可复现
- 代码已提供

QGIS（辅助）：
- Raster → Miscellaneous → Merge
- 目视检查质量
- 适合验证

不推荐：
- ArcGIS Pro（收费，不必要）
```

### 4.3 拓扑关系获取（关键决策）

```
pysheds vs TauDEM对比：

pysheds：
- ❌ 不自动生成拓扑关系表
- 需要自写~650行代码+2周调试
- 开发工作量大

TauDEM StreamNet：
- ✅ 自动生成USLINKNO/DSLINKNO
- 立即可用，准确可靠
- 开发工作量小

决策：使用TauDEM生成拓扑关系
- 在Windows工作站运行
- streamnet.shp包含完整上下游关系
- Python直接读取即可
```

### 4.4 简化流程确认

```
简化后的处理流程（已确认）：

传统复杂流程：
DEM → 填洼 → 流向 → 累积量 → 河网（阈值敏感） → 流域

简化流程（推荐）：
MERIT dir + upa → 累积量阈值 → 初始流域 → SHUC优化

关键洞察：
- 不生成河网，直接基于累积量提取流域
- 对阈值不敏感（SHUC会合并优化）
- 大幅简化流程
```
